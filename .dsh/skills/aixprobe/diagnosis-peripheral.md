# 外设工作状态诊断

## ⚠️ 前置要求

**必须先 `connect()` 建立调试会话。** 如果收到 `"no active session"` 错误，需要重新执行 `connect()`。读外设寄存器前需要先 `halt()` 暂停CPU。

## 适用场景

- GPIO输出不对 / LED不亮不灭
- 串口收发异常 / 无数据
- SPI/I2C通信失败
- 定时器不触发 / 频率不对
- ADC读数异常 / 恒为0
- PWM无输出

## 核心策略

外设不工作的排查顺序（从底层到顶层）：

```
1. 时钟使能了吗？  → 读RCC使能寄存器
2. GPIO配置对吗？  → 读GPIO模式/复用寄存器
3. 外设自身使能了吗？→ 读外设CR的Enable位
4. 参数对吗？      → 读波特率/分频/模式
5. 中断配了吗？    → 读NVIC和外设中断使能
6. 有硬件问题吗？  → 数据通道验证外部信号
```

## 通用诊断：时钟检查

**所有外设问题首先检查时钟！未使能时钟，外设寄存器读出全0。**

需要从SVD中查找芯片的RCC外设寄存器地址。以下为常见STM32F1地址：

```
→ halt()

// AHB外设时钟使能
→ memory_read({"address": "0x40021014", "size": 4})   // RCC_AHBENR

// APB2外设时钟使能（GPIOA/B/C, USART1, SPI1, TIM1, ADC1等）
→ memory_read({"address": "0x40021018", "size": 4})   // RCC_APB2ENR

// APB1外设时钟使能（TIM2-7, USART2/3, SPI2, I2C1/2, CAN等）
→ memory_read({"address": "0x4002101C", "size": 4})   // RCC_APB1ENR
```

> 加载SVD后，可以直接查RCC外设的所有使能位域名称和含义。

## GPIO诊断

```
// 以GPIOA为例（基地址从SVD查询）
// STM32F1: GPIOA基地址 = 0x40010800

→ memory_read({"address": "0x40010800", "size": 4})   // CRL (PA0-7配置)
→ memory_read({"address": "0x40010804", "size": 4})   // CRH (PA8-15配置)
→ memory_read({"address": "0x40010808", "size": 4})   // IDR (输入)
→ memory_read({"address": "0x4001080C", "size": 4})   // ODR (输出)
```

### GPIO模式解码（STM32F1，每个引脚4位）

CRL/CRH每4位控制一个引脚：`CNF[1:0] MODE[1:0]`

| MODE | 含义 |
|------|------|
| 00 | 输入 |
| 01 | 输出10MHz |
| 10 | 输出2MHz |
| 11 | 输出50MHz |

| CNF(输出) | 含义 | CNF(输入) | 含义 |
|-----------|------|-----------|------|
| 00 | 推挽 | 00 | 模拟输入 |
| 01 | 开漏 | 01 | 浮空输入 |
| 10 | 复用推挽 | 10 | 上拉/下拉 |
| 11 | 复用开漏 | 11 | 保留 |

**常见问题**：
- 串口TX引脚应为 `复用推挽`（CNF=10, MODE≠00），配成 `通用推挽` 则无串口输出
- I2C引脚应为 `复用开漏`（CNF=11），配错则通信失败
- ADC引脚应为 `模拟输入`（CNF=00, MODE=00）

### STM32F4/G4/L4 GPIO（不同于F1）

```
// GPIOA基地址 = 0x40020000 (STM32F4)
→ memory_read({"address": "0x40020000", "size": 4})   // MODER (模式)
→ memory_read({"address": "0x40020008", "size": 4})   // OSPEEDR (速度)
→ memory_read({"address": "0x4002000C", "size": 4})   // PUPDR (上下拉)
→ memory_read({"address": "0x40020010", "size": 4})   // IDR
→ memory_read({"address": "0x40020014", "size": 4})   // ODR
→ memory_read({"address": "0x40020020", "size": 4})   // AFRL (复用功能低8引脚)
→ memory_read({"address": "0x40020024", "size": 4})   // AFRH (复用功能高8引脚)
```

MODER每2位一个引脚：00=输入, 01=输出, 10=复用, 11=模拟
AFR每4位一个引脚：AF编号（AF0-AF15对应不同外设）

## UART/USART诊断

```
// USART1基地址（从SVD查询）
// STM32F1: 0x40013800

→ memory_read({"address": "0x40013800", "size": 28})  // 一次读7个寄存器
```

| 偏移 | 寄存器 | 关键位 |
|------|--------|--------|
| 0x00 | SR | TXE[7]=发送空, RXNE[5]=收到数据, ORE[3]=溢出, FE[1]=帧错误 |
| 0x04 | DR | 数据 |
| 0x08 | BRR | 波特率分频值 |
| 0x0C | CR1 | UE[13]=总使能, TE[3]=发送使能, RE[2]=接收使能 |
| 0x10 | CR2 | STOP[13:12]=停止位 |

**波特率计算**：`Baud = Fclk / (16 × BRR)` （BRR含4位小数）

**诊断检查清单**：
1. RCC中USART1时钟使能？
2. TX引脚配为复用推挽？RX引脚配为浮空/上拉输入？
3. CR1中UE=1, TE=1, RE=1？
4. BRR值对应的波特率正确？
5. SR中有无错误标志（ORE/FE/NE/PE）？

## SPI诊断

```
// SPI1基地址（从SVD查询）
→ memory_read({"address": "0x40013000", "size": 12})
```

| 偏移 | 寄存器 | 关键位 |
|------|--------|--------|
| 0x00 | CR1 | SPE[6]=使能, BR[5:3]=分频, MSTR[2]=主模式, CPOL[1], CPHA[0] |
| 0x04 | CR2 | SSOE[2], TXEIE[7], RXNEIE[6] |
| 0x08 | SR | TXE[1]=可发送, RXNE[0]=可接收, BSY[7]=忙, OVR[6]=溢出, MODF[5]=模式错 |

**常见问题**：
- MSTR=0但预期为主模式 → NSS引脚被拉低导致模式切换
- BSY一直=1 → SPI总线死锁
- OVR=1 → 数据溢出，接收速度跟不上

## I2C诊断

```
// I2C1基地址（从SVD查询）
→ memory_read({"address": "0x40005400", "size": 16})
```

| 偏移 | 寄存器 | 关键位 |
|------|--------|--------|
| 0x00 | CR1 | PE[0]=使能, START[8], STOP[9], ACK[10] |
| 0x04 | CR2 | FREQ[5:0]=APB时钟频率(MHz) |
| 0x08 | OAR1 | 自身地址 |
| 0x14 | SR1 | SB[0]=起始位, ADDR[1]=地址匹配, AF[10]=应答失败, BUSY[11] |
| 0x18 | SR2 | MSL[0]=主模式, BUSY[1], TRA[2]=发送模式 |

**常见问题**：
- AF=1 → 从设备未应答（地址错误/设备不存在/硬件连接问题）
- BUSY一直=1 → 总线死锁（SDA被拉低），需要手动时钟恢复
- PE=0 → I2C未使能

## 定时器诊断

```
// TIM2基地址（从SVD查询）
→ memory_read({"address": "0x40000000", "size": 24})
```

| 偏移 | 寄存器 | 关键位 |
|------|--------|--------|
| 0x00 | CR1 | CEN[0]=使能, DIR[4]=方向, CMS[6:5]=对齐模式 |
| 0x08 | SMCR | 从模式 |
| 0x0C | DIER | UIE[0]=更新中断使能 |
| 0x10 | SR | UIF[0]=更新中断标志 |
| 0x24 | CNT | 当前计数值 |
| 0x28 | PSC | 预分频 |
| 0x2C | ARR | 自动重载值 |

**频率计算**：`频率 = Fclk / ((PSC+1) × (ARR+1))`

**常见问题**：
- CEN=0 → 定时器未启动
- ARR=0 → 自动重载值为0，立即溢出
- PSC过大 → 频率极低，看起来没有输出

## ADC诊断

```
// ADC1基地址（从SVD查询）
→ memory_read({"address": "0x40012400", "size": 20})
```

| 偏移 | 寄存器 | 关键位 |
|------|--------|--------|
| 0x00 | SR | EOC[1]=转换完成, STRT[4]=开始 |
| 0x04 | CR1 | 扫描模式等 |
| 0x08 | CR2 | ADON[0]=使能, CONT[1]=连续模式, SWSTART[22]=软件触发 |
| 0x4C | DR | 转换结果 |

**常见问题**：
- ADON=0 → ADC未使能
- 引脚未配置为模拟输入 → 读数不准
- 未执行校准 → 偏移误差大

## 综合诊断决策树

```
外设不工作
├── 寄存器全读为0
│   └── 时钟未使能 → 检查RCC → 使能对应时钟位
├── 寄存器有值但外设不动
│   ├── Enable位=0 → 使能外设
│   ├── GPIO模式不对 → 检查复用配置
│   ├── 参数错误 → 检查波特率/分频
│   └── 中断未使能 → 检查NVIC+外设中断位
├── 有错误标志
│   ├── UART: ORE/FE → 波特率不匹配或噪声
│   ├── SPI: MODF → NSS配置问题
│   ├── I2C: AF → 从设备地址错或硬件问题
│   └── I2C: BUSY锁死 → 需要时钟恢复
└── 寄存器看起来都对
    └── 硬件问题 → 用数据通道(channel_open+channel_read)验证外部信号
```
